# Архитектура игровых систем АЗС

## Ответственность модулей

- Game (scenes/game.gd) — координатор игрового цикла, UI и переходов.
- Work — последовательность NodePath машин и ресурсов Event; проверяет элементы и вставляет события.
- Car — визуальный объект посетителя, проверка своих параметров, расчёт эффекта и запуск анимации. Не изменяет глобальное состояние.
- Character, Event, LinearDialog, Choise — ресурсы контента. Прогресс прохождения диалога не хранится в Character.
- DecisionService — проверяет решение, получает эффект от Car и передаёт его GameState.
- EventService — валидирует Event и применяет его эффект.
- Data (autoload) — единая точка изменения денег и репутации через apply_delta().

## Сценарий решения

1. Игрок нажимает «Согласиться» или «Отказать».
2. Game вызывает DecisionService.apply_decision(car, accepted, Data).
3. Сервис проверяет машину и диапазоны награды.
4. Car.calculate_decision() возвращает пару изменений без побочных эффектов.
5. Data.apply_delta() применяет обе величины или отклоняет операцию целиком.
6. После успеха Car.play_decision() запускает анимацию и отправляет event_requested. Work принимает сигнал и самостоятельно вставляет событие в последовательность.
7. Game переходит к следующему элементу.

## Сценарий события

1. Work возвращает ресурс Event.
2. Game передаёт его в EventService.
3. Сервис проверяет Event и применяет деньги/репутацию через Data.
4. Только после успеха Game показывает текст события.

## Добавление события без изменения GDScript

1. В Godot выберите New Resource и тип Event.
2. Заполните event_text, anim_name, money и respect.
3. Сохраните ресурс в res://content/events/.
4. Выберите нужный Work в сцене и добавьте новый ресурс в массив sequence в нужной позиции.
5. Запустите игру. Событие обрабатывается уже существующим EventService.

Пример готового ресурса: res://content/events/donation.tres. Его можно добавить в любой Work без изменения скриптов.

## Проверка ошибочных данных

- Пустой Event или пустое имя анимации: событие отклоняется до изменения состояния.
- Car без Character: решение отклоняется.
- Некорректный диапазон min/max: решение отклоняется.
- Несуществующий NodePath или неизвестный элемент Work: предупреждение, элемент пропускается.
- Отрицательный итоговый баланс: Data.apply_delta() отклоняет всю операцию.
- Некорректная ссылка на диалог/выбор: Character не допускается к запуску диалога.

Для проверки атомарности зафиксируйте Data.money и Data.respect до вызова, затем убедитесь, что после отклонения оба значения остались прежними.

## Границы зависимостей

Сервисы получают зависимости аргументами и не ищут Autoload или узлы самостоятельно. Game выступает composition root и передаёт сервисам Data. Это позволяет тестировать правила отдельно от сцены.
